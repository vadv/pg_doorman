# Режимы пула

pg_doorman поддерживает два режима пула: `transaction` и `session`. Режим задаётся для пула, при необходимости переопределяется для конкретного пользователя.

Режима `statement` нет.

## Транзакционный режим (рекомендуется)

```yaml
pools:
  mydb:
    pool_mode: "transaction"
```

Поддерживаются:

- Именованные и анонимные подготовленные запросы.
- Pipeline и асинхронный `Flush`.
- Отмена запросов через TLS.

## Сессионный режим

```yaml
pools:
  legacy_app:
    pool_mode: "session"
```

Используйте для клиентов, которым нужны:

- Параметры сессии (`SET search_path`, `SET TIME ZONE`).
- Подписки `LISTEN`.
- Курсоры `WITH HOLD` и advisory-блокировки между транзакциями.

## Переопределение для конкретного пользователя

Режим пула можно переопределить для конкретного пользователя:

```yaml
pools:
  mydb:
    pool_mode: "transaction"
    users:
      - username: "app"
        password: "md5..."
        pool_size: 40
      - username: "admin_tools"
        password: "md5..."
        pool_size: 4
        pool_mode: "session"
```

Полезно, когда одному пользователю (инструменты эксплуатации, миграции) нужна семантика сессии, а основное приложение остаётся в транзакционном режиме.

## Очистка при возврате в пул

По умолчанию используется `cleanup_server_connections: adaptive` без `cleanup_server_query`. Этот вариант сохраняет подготовленные запросы, когда очистка не нужна, и подходит для OLTP-нагрузки на PostgreSQL.

`cleanup_server_query` заменяет встроенные команды очистки. В `adaptive` запрос выполняется по необходимости, в `always` — при каждом возврате использованного соединения. `always` требует заданного запроса, добавляет нагрузку на сервер и может приводить к повторной подготовке запросов. `off` отключает очистку сессии; незакрытые транзакции откатываются в любом режиме.

`adaptive` не гарантирует полную очистку состояния сессии. Для очистки временных объектов, подписок `LISTEN` и сессионных advisory-блокировок используйте `always` с SQL, который освобождает эти ресурсы.

Настройки, ограничения и примеры для PostgreSQL и Greengage см. в [справочнике](../reference/pool.md#cleanup_server_connections).
